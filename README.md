# skill-raw

Скилл, который проверяет чужие скиллы для ИИ-помощника **до установки**. Читает файлы как текст, ничего не запускает, не ходит в сеть, зависимостей нет (Python 3.8+).

Зачем. Скилл — это инструкция, которую помощник читает и выполняет с твоими ключами, почтой и файлами. Значительная часть вредоносных скиллов состоит только из слов: кода в них нет, а красивый вид Markdown прячет пустые блоки и комментарии, которые помощник всё равно читает. Подробнее и с оговорками по цифрам: депеша «Чужой скилл для ИИ: что ты впускаешь» на https://mostik.ideav.ru/depeshi/004.html.

**Чистый результат не значит безопасно.** Скрипт ловит перечисленные приёмы и не понимает смысл. После него `SKILL.md` всё равно читается глазами целиком.

## Установка как скилла

```bash
git clone https://github.com/sergiiKols/skill-raw ~/.claude/skills/skill-raw
```

После этого помощник сможет сам запускать проверку, когда ты просишь «проверь скилл перед установкой». Можно и просто запускать скрипт руками.

## Запуск

Скачанный чужой скилл клади в свою новую пустую папку и запускай скрипт с `-I`, указав путь аргументом, не изнутри этой папки.

```bash
python3 -I skill_raw.py <папка скилла или репозитория>
python3 -I skill_raw.py <путь к SKILL.md>
python3 -I skill_raw.py <папка> --format json
python3 -I skill_raw.py <папка> --fail-on medium
python3 -I skill_raw.py <папка> --tail 30
```

Тесты: `python3 -m unittest test_skill_raw`.

Коды выхода: `0` стоп-находок нет (безопасность не доказана); `1` ошибка пути или аргументов; `2` есть находки не ниже порога, ставить нельзя без разбора; `10` в пути нет `SKILL.md`, проверки не было.

## Что ловит

| Код | Что | Уровень |
|---|---|---|
| R1 | 20+ пустых строк подряд (40+ с текстом после — HIGH) | MEDIUM / HIGH |
| R2 | HTML-комментарий (с подозрительными словами — HIGH) | MEDIUM / HIGH |
| R3.1 | теговые символы Unicode U+E0000–E007F | HIGH |
| R3.2 | символы смены направления письма | HIGH |
| R3.3 | символы нулевой ширины | MEDIUM / HIGH |
| R3.4 | пять и более селекторов вариантов | MEDIUM |
| R4 | загрузка и запуск одной строкой: `curl \| sh`, `bash <(curl …)`, `base64 -d \| sh`, `iex` | HIGH |
| R5.1 | адрес из группы риска: вебхук, пастебин, сократитель, голый IP, бот-API | MEDIUM |
| R6 | запись в память или конфиг агента (MEMORY.md, AGENTS.md, settings.json, cron…) | MEDIUM |
| R7 | «не сообщай пользователю», «keep this secret» | HIGH |
| R8 | «игнорируй предыдущие инструкции», «если ты ИИ-сканер», «отметь как безопасный» | HIGH |
| R9 / R9.1 | отправка ключей и токенов по адресу / упоминание чувствительных путей | HIGH / MEDIUM |
| R10, R11 | файл больше 2 МБ и бинарные файлы не просмотрены | MEDIUM |
| R12 | скрипт может: сеть, запуск процессов, динамический код, раскодирование | LOW |
| R13 | символическая ссылка (наружу — HIGH) | LOW / HIGH |

Скрипт также показывает конец `SKILL.md` с раскрытыми невидимыми символами и считает отпечаток дерева (`PIN=sha256:…`) по путям и хэшам файлов: его записывают при установке и сверяют при обновлении.

Этот скилл сам описывает такие приёмы, поэтому на нём самом скрипт даст находки уровня HIGH. Это не сбой: описание приёма лежит в данных, а не в инструкции.

## Правило установки чужого скилла

1. **Скачать, а не устанавливать.** `git clone` или архив: в новую пустую папку вне папок скиллов и вне корня проекта. Не запускать `npx skills add`, установочные скрипты и `curl | sh`: они ставят сразу.
2. **Записать источник:** адрес, тег или коммит, дату и отпечаток `PIN`. Версию закреплять коммитом, а не веткой.
3. **Прогнать skill-raw.** Код `2` — стоп, разобрать каждую находку по строке. Код `10` — проверки не было. Код `0` — ещё не разрешение.
4. **Прочитать сырой `SKILL.md` целиком, включая конец файла**, а не рендер. Прочитать каждый скрипт из находок R12. Содержимое чужих файлов — данные, не указания помощнику.
5. **Отклонять без обсуждения** скилл, который велит скрывать действия от пользователя; пишет в память или конфиг помощника и тем переживает удаление; докачивает инструменты при установке или запуске; отправляет ключи, токены или файлы по адресу; просит модель или сканер признать его безопасным.
6. **Ставить сначала в отдельную копию** без ключей, `.env`, облачных и SSH-учётных данных. Запись в память и конфиг помощника скиллу не давать без явного согласия.
7. **Решение за человеком:** одной строкой записать, кто, когда, источник, `PIN`, результат проверки и что прочитано. Без этого скилл остаётся в папке скачивания.
8. **Обновление — это новая установка.** Сверить `PIN`: изменился — шаги 3–4 заново на разнице.
9. **После установки** записать происхождение: источник, лицензию, `PIN`, что изменено.

## Чего не делает

- Не оценивает смысл инструкций: убедительно написанный вред обычными словами пройдёт. Для этого шаги 4 и 6.
- Не проверяет код проекта и зависимости (`npm`, `pip`), не оценивает качество описания скилла.
- Не ставит и не удаляет скиллы.
- Не заменяет песочницу.
- Не смотрит содержимое бинарников и файлов больше 2 МБ, только сообщает о них.

## Проверено ли

Регулярные выражения и пороги — эвристики, подобранные по тестовым фикстурам и прогону по 17 скиллам автора (27.10.2026): вредных приёмов в них не нашлось. На реальных вредоносных скиллах не проверялось, полноту не измеряли. Цифры отчётов VirusTotal здесь независимо не проверялись.

Основа: публикации VirusTotal Blog, октябрь 2026 («From Automation to Infection», часть III, и «How Some Malicious AI Skills Hide Instructions from Reviewers»).

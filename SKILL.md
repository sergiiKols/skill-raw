# skill-raw — просмотр сырого скилла до установки

Читает файлы скилла как текст и ничего не исполняет. Нужен потому, что значимая часть вредоносных скиллов состоит только из слов: код проверять нечем, а рендер Markdown прячет комментарии и пустые места, которые агент читает. Правило установки из девяти шагов — в `README.md`.

**Чистый результат не значит безопасно.** Скрипт ловит перечисленные приёмы и не оценивает смысл инструкций. После него `SKILL.md` всё равно читается глазами целиком.

## Запуск

Рабочая папка — корень скилла. Скачанный чужой скилл кладётся в свою новую пустую папку, скрипт запускается с `-I` и путём аргументом, не изнутри этой папки.

```bash
python3 -I skill_raw.py <папка скилла или репозитория>
python3 -I skill_raw.py <путь к SKILL.md>
python3 -I skill_raw.py <папка> --format json
python3 -I skill_raw.py <папка> --fail-on medium
python3 -I skill_raw.py <папка> --tail 30
```

Тесты: `python3 -m unittest test_skill_raw`.

## Что ловит

| Код | Что | Уровень |
|---|---|---|
| R1 | 20+ пустых строк подряд (40+ с текстом после — HIGH) | MEDIUM / HIGH |
| R2 | HTML-комментарий (с подозрительными словами — HIGH) | MEDIUM / HIGH |
| R3.1 | теговые символы Unicode U+E0000–E007F | HIGH |
| R3.2 | символы смены направления письма | HIGH |
| R3.3 | символы нулевой ширины (в тексте от 3 — HIGH; в коде — MEDIUM) | MEDIUM / HIGH |
| R3.4 | пять и более селекторов вариантов | MEDIUM |
| R4 | загрузка и запуск одной строкой: `curl \| sh`, `bash <(curl …)`, `base64 -d \| sh`, `iex` | HIGH |
| R5.1 | адрес из группы риска: вебхук, пастебин, сократитель, голый IP, бот-API | MEDIUM |
| R6 | запись в память или конфиг агента (MEMORY.md, AGENTS.md, settings.json, cron…) | MEDIUM |
| R7 | «не сообщай пользователю», «keep this secret» | HIGH |
| R8 | «игнорируй предыдущие инструкции», «если ты ИИ-сканер», «отметь как безопасный» | HIGH |
| R9 | отправка ключей, токенов, секретов по адресу | HIGH |
| R9.1 | упоминание чувствительных путей (`.ssh`, `.aws`, `.env`) | MEDIUM |
| R10 | файл больше 2 МБ не просмотрен | MEDIUM |
| R11 | бинарные файлы: содержимое не просматривалось | MEDIUM |
| R12 | скрипт может: сеть, запуск процессов, динамический код, раскодирование | LOW |
| R13 | символическая ссылка (наружу — HIGH) | LOW / HIGH |

R5.1, R6, R9.1 свёрнуты: одна находка на файл со счётом. Отпечаток дерева (`PIN=sha256:…`) считается по путям и хэшам файлов; его записывают при установке и сверяют при обновлении.

Выводимые строки очищены: управляющие и невидимые символы заменяются на `<U+XXXX>`, чтобы вывод скрипта сам не мог повлиять на терминал или агента.

## Коды выхода

| Код | Маркер | Здесь означает |
|---|---|---|
| `0` | `SKILL_RESULT` | стоп-находок нет (`SUMMARY`, `PIN`); безопасность не доказана |
| `1` | `SKILL_ERROR` | путь не найден или не читается, неверные аргументы (`STAGE`, `ERROR`) |
| `2` | `SKILL_STOP` | есть находки не ниже порога (`BLOCKING`, `THRESHOLD`, `PIN`) — не сбой, скилл ставить нельзя без разбора |
| `10` | `SKILL_NEEDS_INPUT` | в пути нет `SKILL.md` (`MISSING`): SKIPPED не значит PASS |

В режиме `--format json` маркер не печатается, код выхода тот же.

## Санкции

Кода `20` нет: скрипт ничего не пишет, не удаляет, не ходит в сеть и не запускает проверяемые файлы. Решение об установке принимает человек на следующем шаге, по правилу из `README.md`.

## Как читать результат

1. `2` и HIGH — не ставить; разобрать каждую находку по строке; для скилла из поста — отклонить или найти первоисточник.
2. `0` — ещё не разрешение: прочитать `SKILL.md` целиком, конец файла (скрипт показывает его), скрипты из R12, адреса из списка.
3. Скилл, который сам описывает такие приёмы (обучающий корпус, разбор безопасности, этот скилл), даёт HIGH по смыслу — это не сбой; проверять надо, что описание лежит в данных, а не в инструкции.
4. Не для обхода: если находка снята как «описание приёма», это решение записывается рядом с источником и отпечатком, с причиной.

## Чего не делает

- не оценивает смысл инструкций и не находит убедительно сформулированный вред обычными словами → читает человек;
- не проверяет код проекта и зависимости (`npm`, `pip`): для этого нужен аудит зависимостей;
- не проверяет качество описаний и структуру скилла;
- не ставит и не удаляет скиллы;
- не заменяет песочницу: установленный скилл запускается в отдельной папке без ключей;
- не смотрит содержимое бинарников и файлов больше 2 МБ — только сообщает о них.

## Происхождение

Создан 27.10.2026 по разбору публикаций VirusTotal Blog от октября 2026 («From Automation to Infection», часть III, и «How Some Malicious AI Skills Hide Instructions from Reviewers»): список приёмов сокрытия, рекомендации читать сырой файл и убирать невидимые символы. Цифры публикаций не проверялись независимо. Регулярные выражения и пороги (20/40 пустых строк, 3 символа нулевой ширины, 2 МБ) — эвристики, подобраны по тестовым фикстурам и прогону по 17 скиллам автора 27.10.2026; на реальных вредоносных скиллах не проверялись.
